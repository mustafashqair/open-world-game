# v50g4-2 texture build

LOW/very-low only. Disable with `?v50g4t=0` or `?v50g4=0` and reload.

Tab's port onto v50g3 ships the real KTX2 set (106 files, 53 textures × low/vlow, ~20 MB,
built with toktx 4.4.2 by `tools/build_v50g4_textures.py`). The loader uses the original WebP
for anything not in the manifest. It also falls back to WebP on fetch/transcode errors. It preserves callers'
texture transforms, wrapping, filters and color-space choices. Basis transcoder files
already exist in vendor/three170/examples/jsm/libs/basis/.

Install [KTX-Software 4.x](https://github.com/KhronosGroup/KTX-Software/releases)
with `toktx` on PATH. From the repository root run:

```sh
python3 tools/join_large_files.py
python3 -m pip install Pillow
python3 tools/build_v50g4_textures.py
python3 -m http.server 8000
```

The script writes genuine UASTC + Zstd KTX2 with mipmaps, max edge 512 on LOW,
256 on very-low. It uses lower-left row orientation to match external TextureLoader UVs, linear normal maps
stored as plain RGB (no `--normal_mode`: that layout puts X in RGB and Y in alpha, which three.js reads as wrong
normals — it made the village ground dark and speckled), sRGB color maps and excludes HIGH
`-hq` assets. It includes large external city, village/v4 and landmarks textures,
including the original 4096x4096 gravel. Existing `-l` files get their own variants.
Only successful completion publishes the manifest. Commit `v50g4/textures/` and
`v50g4/textures-manifest.json` together. Inspect `window.__g4Textures.compressed`
while visiting village/city/landmarks; force a missing file to check WebP fallback.

Embedded GLB images are not converted by this script. Their runtime caps remain
unchanged. Compare normals/mip seams/texture appearance on target hardware before
publishing. No compression savings are claimed until the generated assets ship.
MEDIUM/HIGH never request the manifest or compressed files.

## Fixes in Tab's port (v50g3)

- **texSubImage2D failures (18–19 of 47 textures):** root cause is the landmarks builder (PMQ `tex()`), which
  copies only `x.image` out of the loaded texture into its own plain `THREE.Texture`. A KTX2 result keeps its data
  in `mipmaps`; its `.image` is just `{width, height}`, so the plain texture tried to upload that object with
  `texSubImage2D` → "Overload resolution failed". PMQ now adopts the compressed texture itself in place of its own
  (same wrap/anisotropy/colour space, every material slot that pointed at the old one is switched). Not `.clone()`.
- Clones of a KTX2 result keep `isCompressedTexture` (Texture.copy does not carry it).
- The WebP fallback fills the caller's texture exactly like stock TextureLoader (`texture.image = image`).
